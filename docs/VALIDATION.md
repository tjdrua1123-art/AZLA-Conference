# v0.6 검증 보고서

2026-11-04. 자유로운 회의 날짜 선택·변경, 넓은 진행 내용과 회의 결정의 두 칸 배치, 진한 텍스트와 이전 계획 기록 보존을 적용했습니다. 이전 자료 이어 쓰기와 안건 삭제·복원을 유지합니다. 여섯 분류 탭과 회의 전체 녹음/자동 요약 흐름은 유지합니다.

- TypeScript 검사, 프로덕션 빌드 통과.
- 단위/실제 PostgreSQL 엔진(PGlite) 통합 테스트 23개 통과: 분류 순서, 이전 데이터 호환, 공동 수정 병합·충돌, 서버 전용 DB 권한, AI 한도, 녹음 단계별 저장·실패 후 재시작·긴 전사 분할 검사. 기존 v0.1 정책 검사도 유지합니다.
- 프로덕션 빌드 대상 Chromium 브라우저 검증 통과. 탭 전환 및 가속한 4분 경계에서 두 녹음 구간이 순서대로 저장·정리됨을 확인했습니다. 브라우저 테스트는 실제 Chromium MediaRecorder와 가상 마이크를 사용하며, OpenAI 응답은 테스트용으로 제어합니다. 각 탭의 내용 분리·입력/수정·이미지 검토·탭 이동 중 녹음·회의 종료 자동 처리·요약 영속화·실패 후 재시도·원본 포함 ZIP 복원·동시 편집·마이크 거부·모바일을 검사합니다.
- 실제 OpenAI API, 호스팅 Supabase Storage/DB, 회의실 장비와 장시간 실녹음은 아직 미검증입니다. 테스트용 AI 응답을 실제 전사 정확도 검증으로 주장하지 않습니다. 운영 배포 성공도 Git 푸시와 별도로 확인해야 합니다.

## 이번 변경의 추가 검증

- 1366×768 PC: 넓은 진행 내용/회의 결정 두 칸의 가로 배치, 입력 창 외부 스크롤 없이 저장 버튼 노출, 저장 후 편집 지속, Ctrl/Cmd+S 반복 저장 후 첨부 보존을 확인했습니다.
- 취합 화면: 전체 문서 세로 스크롤 대신 본문 영역 확보, 긴 내용 펼치기/접기, 이전 회의 대비 변경 강조와 나란히 비교, 새로고침 후 수정 내용 유지, 모바일 가로 넘침 방지를 확인했습니다.
- 다음 회의 생성: 보고·계획·결정·첨부 원본 경로 유지, 주차별 별도 ID, 녹음 제외, 이미 준비된 주 재사용과 수정 보존, 삭제한 안건의 이월 제외를 확인했습니다. 날짜를 변경한 준비 회의의 재사용과 두 직원의 동시 생성은 모델 테스트로 검사했습니다.
- 안건 삭제/복원: 해당 주차의 목록에서 제외, 휴지통 복원, 파일 접근 유지, 원래 주차 불변을 브라우저에서 확인했습니다. 삭제와 동시 내용 수정의 충돌도 단위 테스트로 검사했습니다.
- 공유 링크 접근/서명 쿠키/잘못된 입력 거부는 v0.4에서 별도 로컬 서버와 테스트용 자격증명으로 통과했고, 이번 변경에 해당 접근 로직 수정은 없습니다. 실제 Supabase 호출을 대체하는 검증은 아닙니다.

- 수요일 회의 → 금요일로 다음 회의 생성 → 화요일로 기존 날짜 변경 → 원래 회의에서 준비된 회의 재사용을 브라우저에서 검사했습니다. 날짜 선택창을 취소하면 회의가 추가되지 않습니다. 한국시간 오늘 기본값과 자정 경계는 단위 테스트로 확인했습니다.
- 새 계획 입력과 취합표 열이 없는지 확인하고, 이전 버전의 계획 데이터가 있는 저장소를 실제로 불러와 읽기·수정 저장·이월·새로고침 후 원문이 유지되는지 확인했습니다.
- 입력 본문·취합 본문·이전 회의 읽기 전용 비교 글자는 흰 배경 대비 7:1 이상을 검사했습니다.

`npm run test:readability`는 `TEST_BASE_URL`로 지정한 실행 서버를 검사합니다. 스크린샷은 `/tmp`에만 생성하며 공개 Git 저장소에 실제 회의자료를 포함하지 않습니다.

## 작성·취합 화면 통합

상단 ‘내용 작성 / 취합 회의자료’ 전환과 별도 표 직접 입력 모드를 제거하고 기존 취합표 하나로 통일했습니다. 안건 등록·연필 수정 버튼의 입력 창에서 저장합니다. TypeScript 검사와 프로덕션 빌드를 통과했고, 두 브라우저의 입력 창에서 같은 안건의 서로 다른 필드를 수정해 모두 보존되는지 확인했습니다. 기존 녹음·요약·백업 브라우저 검사와 날짜·이월·삭제·복원·가독성 검사도 통과했습니다.

## 프로젝트 회의 보드

- 표 대신 제품명과 안건 제목이 구분되는 프로젝트 카드를 적용했습니다. 진행 내용·회의 결정·참고 이미지/PDF는 같은 카드에 표시하며, 여러 안건이 있을 때 바로가기 버튼으로 해당 카드로 이동하고 키보드 포커스도 옮깁니다.
- 비교 가능한 이전 보고에 없는 문장을 최대 세 줄 골라 먼저 보여줍니다. 생성형 요약·임의의 중요도 판정은 하지 않습니다. 전체 펼치기와 인쇄에서 원래 순서의 전체 문장이 보이는지 검사했습니다. 삭제만 있었을 때는 원문과 비교 버튼으로 확인하며 삭제된 내용을 새로 지어내지 않습니다.
- 여러 프로젝트의 카드·바로가기·결정 유무 표시와 모바일 가로 넘침을 브라우저에서 검사합니다. 회의 결정은 저장된 기록의 표시이며 별도의 대표 승인 상태를 추정하지 않습니다.
- 기존 날짜 변경·이월·안건 삭제/복원·파일·전주 비교·녹음/요약·동시 편집 검증을 유지합니다. 실제 회사 자료는 테스트 스크린샷이나 공개 저장소에 추가하지 않습니다.
