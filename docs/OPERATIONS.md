# 운영 및 백업 (v0.5)

## 팀 공유의 접근 범위

계정·역할 구분을 제거했습니다. 공유 링크 보유자는 회의록, 모든 파일과 검토 의견을 읽고 수정할 수 있습니다. 담당자/검토자 이름은 자유 입력이므로 법적 서명이나 사용자 인증 감사 기록으로 사용하지 않습니다. 기존 Supabase Auth 정책을 공개로 바꾸지 않고, 새 v0.2 데이터는 서비스 역할 서버와 제한된 서명 URL만 사용합니다. 공유 링크를 외부에 전달한 경우 키를 교체하고 재배포합니다.

## 저장·동시 수정

- 표 안에서 직접 수정한 내용은 상단 ‘회의자료 저장’ 또는 Ctrl/Cmd+S로 저장합니다. 안건 입력 창의 저장, 삭제/복원, 다음 주 준비와 시안 검토는 즉시 저장을 시도하므로 완료/오류 표시를 확인합니다.
- 다른 안건이나 서로 다른 필드의 변경은 기준/내 변경/최신 서버 내용을 비교해 합칩니다. 같은 필드가 충돌하면 덮어쓰지 않고 내 입력을 유지합니다. 전체 백업을 먼저 내보내고 최신 회의와 대조합니다. 저장 중 추가 입력도 유지됩니다.
- ‘최신 불러오기’는 미저장 내용을 버릴 수 있어 확인을 받습니다. 다음 주 회의는 지난 보고·계획·결정·자료를 편집 가능한 별도 안건으로 이어받고 미완료 업무의 같은 ID를 연결합니다. 시안 원본 경로를 재사용하고 과거 검토 이력임을 표시합니다. 확정 상태와 녹음은 새로 시작합니다.
- 기본 목록은 워크스페이스 JSON 전체를 읽고 버전 단위로 저장합니다. 저장 요청은 JSON 2MiB, 회의 최대 1,000개/안건 각 300개입니다. 수년의 자료가 쌓이기 전에 회의별 행·페이지 조회로 전환해야 합니다. 이 버전은 팀 규모의 회의 운영을 위한 단순한 초기 저장 구조입니다.

## 파일·PPT·컨펌

PPTX의 텍스트와 지원 이미지 형식만 가져옵니다. 업무 보고/업무 계획 표는 인식하지만 임의의 PPT 레이아웃을 완전히 해석하지 않습니다. 도형·차트·SVG·EMF·WMF·외부 링크 이미지는 가져오지 않으므로 원본과 비교합니다. 표가 아닌 여러 제품이 섞인 페이지는 한 안건으로 가져오며 가져오기 후 제품별로 나눌 수 있습니다. 승인 여부·담당자·기한은 추론하지 않습니다.

시안 검토는 승인/수정 요청/대기를 기록하고 검토자·시각·의견을 누적합니다. 수정 요청에는 구체적 의견, 모든 상태 기록에는 검토자 이름을 요구합니다. 같은 파일을 덮어쓰지 않으며 수정 시안은 새 파일로 추가합니다. 자동 악성코드 검사 서비스는 포함하지 않습니다. 신뢰하는 팀 자료의 허용 형식만 업로드합니다.

PPT/백업 압축 해제 총 크기는 200MiB, 단일 ZIP 항목은 40MiB, 입력 파일은 100MiB 이하입니다. 초과하는 자료는 분할합니다. 자료 첨부 후 회의 저장 전에 탭을 종료하면 파일이 저장돼 있어도 회의 연결 정보가 미저장일 수 있습니다. 업로드 후 연결 저장 실패한 고아 객체는 관리자 점검 대상으로 남기며 자동 삭제하지 않습니다.

## 백업·복구

- 앱의 전체 백업은 **회의 JSON + 모든 연결 파일 원본**을 ZIP으로 내보냅니다. 브라우저 모드에서는 필수입니다. 브라우저 사이트 데이터를 지우면 IndexedDB도 사라집니다. 다른 컴퓨터에 자동 공유되지 않습니다.
- 백업 복원은 현재 워크스페이스 목록을 교체하고 다시 저장하는 작업입니다. 복원 전 현재 백업을 확보합니다. 공유 모드 복원은 팀에 알린 뒤 수행합니다.
- Supabase DB 백업만으로 Storage 원본은 복원되지 않습니다. Supabase Pro의 보존/PITR 범위를 확인하고 DB 논리 덤프와 Storage 파일을 함께 보관합니다. 승인된 암호화 오프라인 사본으로 정기 백업하고 별도 테스트 프로젝트에서 복원과 파일 열기를 검사합니다. 별도의 실시간 DB/파일 서비스를 사용하지 않습니다.
- `conference_history`는 전체 저장 이력을 보존하며 UI는 최근 50개를 표시합니다. 로컬 이력 역시 IndexedDB에 보존합니다. 보존 기간·퇴사 후 링크 변경·녹음 삭제·복구 목표는 회사 정책으로 정합니다.
- 기존 v0.1 회의/파일은 자동 이관하지 않습니다. 실제 데이터가 존재하면 원본 백업과 매핑 검토를 포함한 이관 작업을 별도로 진행합니다.

## 녹음·AI

마이크는 HTTPS와 지원 브라우저가 필요합니다. 녹음은 메모리에 보관하다 종료 시 첨부하며 19MiB 이상이면 자동 종료합니다. 최종 청크로 20MiB를 넘으면 업로드를 거절하고 복구 다운로드를 제공합니다. 탭/브라우저 충돌 전에 미저장 녹음이 손실될 수 있으므로 구간별로 녹음합니다. 녹음 중에는 AI 창을 닫지 못하게 합니다.

참석자 녹음 동의와 회사의 외부 AI 전송 승인이 전제입니다. 팀 전체 한국시간 하루 40회 한도는 원자적으로 예약하며 실패 요청도 포함합니다. 금액 상한은 아니므로 OpenAI 프로젝트 예산/사용량도 확인합니다. 메모+안건 최대 90,000자, 전사 최대 60,000자, 출력 6,000토큰입니다. 요약 토큰 사용은 DB에 남기고 전사 과금은 OpenAI 내역과 대조합니다. 근거 인용이 존재해도 AI 요약은 틀릴 수 있어 제품명·수치·담당자·날짜를 사람이 확인합니다.

## 실제 연결 인수 테스트

1. 두 브라우저에서 같은 공유 링크로 열고 ‘팀 공유 저장소’를 확인합니다. 일반 주소/틀린 키/만료 쿠키에서는 비공개 데이터가 열리지 않는지 검사합니다.
2. 각자 다른 안건 또는 다른 필드 작성→동시 저장→모두 보존, 같은 필드 작성→충돌→입력 유지 여부를 확인합니다.
3. 업로드·서명 다운로드·만료·확대·시안 비교·승인→수정 요청→이력, 파일 포함 백업→다른 브라우저 복원을 확인합니다.
4. 제공된 PPT와 가져온 보고/계획/이미지를 대조하고 담당자·기한·컨펌 여부를 수동 확인합니다.
5. 실제 마이크 녹음, 실패 복구, OpenAI 한국어 전사/초안, 일일 한도와 서버 타임아웃을 확인합니다.
6. 인쇄 전에 이미지 로딩 완료, 페이지 줄바꿈, 전체 안건/업무 포함 여부를 확인합니다.

## v0.3 회의 전체 녹음 운영

- 화면은 신제품개발/디자인/생산관련업데이트/보류/중단/회의 녹음 내용 여섯 탭이며 각 분류의 안건만 표시합니다. 작성자 이름 입력/표시를 제거했습니다. 자유 입력 검토자와 업무 담당자 기록은 필요한 곳에만 남습니다.
- 녹음 제어는 분류별 화면 밖에 있어 탭 이동에 영향을 받지 않습니다. 브라우저 새로고침·종료, OS 절전, 마이크 분리·권한 철회까지 녹음 지속을 보장하지 않습니다. 마이크 중단은 오류로 알립니다. 회의 종료 전 원래 브라우저를 닫지 마세요.
- 녹음은 4분마다 독립 파일로 저장해 파일당 20MiB 제한과 서버 처리 시간에 대응합니다. 구간 재시작 경계에 미세한 공백이 발생할 수 있으므로 실장비에서 검증해야 합니다. 아직 마감되지 않은 구간은 브라우저 충돌 시 손실될 수 있습니다. 완료된 구간은 업로드 전 IndexedDB 복구 캐시에 저장합니다.
- 종료 시 각 원본 구간과 종료 정보를 먼저 저장합니다. 그 다음 구간별 전사와 긴 전사 분할 요약을 수행해 결과를 매 단계 저장합니다. 마지막 요약도 자동 저장되지만 ‘검토 완료’로 자동 표시하지 않습니다. 기존 진행 보고나 회의 결정을 자동 수정하지 않습니다.
- 저장에 실패하면 원본 복구 파일 다운로드를 시도하며, 같은 브라우저의 ‘녹음 복구 확인’에서 완료 구간의 로컬 캐시를 다시 올릴 수 있습니다. 다른 PC에는 복구 캐시가 없으므로 원래 녹음한 PC에서 수행합니다. 녹음이 중단된 상태로 남아 있으면 저장된 구간을 확인하고 복구/다시 정리를 수행합니다.
- 한국어 전사는 구간마다 요청하며 실패 시 이미 완료한 구간을 다시 과금하지 않고 다음 구간부터 재시작합니다. 요약은 전사를 최대 24,000자씩 나누어 요청하며 원문을 잘라 버리지 않습니다. 요약 재시도는 다시 비용이 발생할 수 있습니다. 팀 하루 40회 한도는 전사·요약 요청 전체에 적용됩니다.
- ‘기존 녹음 추가’로 파일을 넣은 경우 길이는 자동 계산하지 않고 0초로 표시될 수 있습니다. 원본 재생기의 길이를 확인합니다. AI로 보내기 전 동의를 확인합니다.
- 원본 다운로드 ZIP은 순서대로 정렬된 녹음 구간·전사·요약을 담습니다. 여러 WebM 구간을 단순 바이너리 결합한 손상된 단일 파일을 제공하지 않습니다. 전체 회의 백업에도 모든 원본 구간이 들어갑니다.

### 추가 인수 테스트

실제 회의 시간만큼(예: 60~90분) 녹음해 구간별 재생·음질·구간 경계·순서·전사 정확도를 확인하세요. 모든 분류 탭 왕복, 업로드 도중 연결 끊김과 복구, AI 타임아웃/한도 초과, 종료 처리 중 페이지 이탈, 마이크 거부/분리도 확인합니다. 예전 v0.2의 개별 안건 녹음/19MiB 자동 종료 안내는 이 회의 전체 녹음 흐름으로 대체됩니다.

## v0.4 주차별 안건 보존과 삭제

- 다음 주 회의는 이전 회의와 별도 안건 ID를 사용합니다. 같은 이전 회의/주차의 준비 요청은 같은 ID를 사용해 중복 생성을 방지하며, 이미 작성한 다음 주 내용은 다시 복사해 덮어쓰지 않습니다. 원본 파일은 공유하지만 검토 의견/표시 상태는 주차별로 분리합니다.
- 삭제는 선택한 주차 안건에 삭제 시각을 기록하는 방식입니다. 표·분류 개수·이월에서 제외하고 ‘삭제한 안건’에 남겨 복원합니다. 다른 주차와 물리 파일에는 영향이 없습니다. 이미 준비된 미래 회의는 자동 변경하지 않습니다.
- 삭제/복원과 다른 직원의 같은 안건 수정이 동시에 발생하면 충돌로 알립니다. 삭제된 내용이 다른 직원의 수정을 조용히 숨기지 않도록 합니다. 충돌 시 내 입력을 백업하고 최신 자료와 비교합니다.
- 전체 백업은 삭제한 안건과 연결 파일도 보존합니다. 삭제는 용량 회수나 녹음/파일 영구 파기 기능이 아닙니다. 영구 파기가 필요한 경우 보존 정책에 따라 모든 주차·수정 이력·백업에서의 참조를 검토해야 합니다.
- 비교 화면의 전주 내용은 연결된 이전 회의의 현재 저장 값을 조회합니다. 전주 원본을 나중에 수정하면 비교 기준도 달라지지만, 이번 주 내용은 자동으로 덮어쓰지 않습니다.

추가 인수 테스트: 실제 두 직원이 같은 다음 주 회의를 동시에 준비해 한 회의만 생기는지, 복사한 안건을 수정/삭제해도 이전 주가 유지되는지, 삭제한 안건의 복원·첨부 열기·다음 주 이월 제외가 정상인지 확인합니다. 기존 v0.2 DB에는 별도 SQL 적용이 필요 없습니다.

## v0.5 날짜 선택과 진행 내용 중심 화면

- 월요일 고정 생성 대신 첫 회의는 한국시간 오늘을 제안하고, ‘다음 회의 만들기’에서 원하는 날짜를 먼저 정합니다. 이전 회의 +7일은 제안값일 뿐 다른 요일/간격을 선택할 수 있습니다. 취소하면 새 회의를 생성하지 않습니다.
- 같은 원본 회의에서 선택한 날짜에 이미 준비한 회의가 있으면 기존 편집 내용을 유지하며 엽니다. 일정이 바뀌면 ‘날짜 변경’을 사용합니다. 다른 날짜를 지정하면 별도 회의 생성으로 취급됩니다.
- 새 ‘다음 계획’ 입력은 제거했습니다. 진행 내용과 회의 결정만 작성하며, 과거 `plan` 데이터는 삭제하거나 자동으로 보고 내용에 합치지 않습니다. ‘이전 버전의 계획 기록’에서 읽고 저장·이어받기·백업에서 보존합니다. DB 변경은 필요 없습니다.
- 본문·입력·비교 화면의 텍스트를 진하게 바꾸고 진행 내용 공간을 확장했습니다. 긴 자료는 펼쳐 읽는 방식과 삭제/복원 동작을 유지합니다.
