# 운영 전 테스트 및 데이터 관리

## 실제 서비스 인수 테스트 (아직 미실행)

- 관리자/작성자/열람자/비활성 직원 및 비로그인 브라우저를 각각 준비합니다. 초대·비밀번호 설정·로그인·로그아웃·세션 갱신을 확인하고 직접 Supabase REST 호출로도 권한 우회가 불가능한지 확인합니다. 임의 회원가입을 Auth API에서도 시도해 차단을 확인합니다.
- 작성자가 회의 생성 → 임시저장 → 수정 → 확정, 다른 직원 열람, 동시 두 탭 저장 충돌, 이전 버전 열람, 확정 기록의 재수정 후 새 버전 생성을 확인합니다. 확정은 법적 전자서명/불변 보존 기능이 아닙니다.
- JPG/PNG/WebP 여러 장, 20MB 경계, 큰 파일 거절, PDF와 한글 파일명 다운로드, 이미지 확대, 비로그인 링크 접근 불가, 서명 URL 만료를 확인합니다. 악성 파일 탐지 서비스는 포함하지 않았으므로 신뢰하는 직원의 허용 형식만 업로드하세요. SVG/HTML은 허용하지 않습니다.
- Chrome/Edge/Safari에서 HTTPS 마이크 권한 허용·거절·중단·업로드 실패 시 로컬 복구 다운로드를 확인합니다. 녹음은 메모리에 버퍼링되며 탭 종료/브라우저 충돌 전에 저장되지 않은 녹음은 잃을 수 있습니다. 19MiB 이상 자동 종료(최종 20MiB 초과 시 업로드 거절), 장시간 회의는 구간별 녹음으로 운영합니다. 실제 녹음 전 참석자 동의를 받습니다.
- 실제 한국어 녹음 전사 후 제품명·측정 수치·담당자 인식 정확도를 확인합니다. 파일 재생 UI는 없으며 다운로드 후 확인합니다. 메모만/전사만/혼합 입력, 애매한 날짜, 잘못된 지시문, 빈 원문, 긴 입력, AI 오류·일일 한도 초과·외부 API 타임아웃을 확인합니다. 저장 전 원문·초안·최종 회의록을 비교합니다.
- 같은 업무 재등록, 이전 주 미완료 자동 이월(같은 task ID), 완료 업무 제외, 같은 날짜 회의에는 이월하지 않는 동작, 담당자 변경·마감일 변경·제품별 열람을 확인합니다. 회의 생성 시점 이후 새로 생긴 업무는 이미 생성한 다음 회의에 소급 자동 연결되지 않습니다.
- 검색(날짜+제품+키워드), 모바일, 인쇄/PDF 긴 문서 줄바꿈과 사진 별도 출력 절차를 확인합니다. 현재 PDF는 텍스트 회의록/연결 업무 중심이며 첨부 원본을 병합하지 않습니다.

## 장기 보관 및 백업

- Supabase Pro DB 자동 백업/PITR의 실제 구독 범위·보존 기간·복원 절차를 계정에서 확인합니다. **DB 백업은 Storage 원본 파일을 복원하지 않습니다.** DB 덤프만으로 사진이 백업됐다고 가정하지 마세요.
- 기본 저장소는 계속 Supabase 하나입니다. 삭제/덮어쓰기 정책을 제공하지 않아 앱에서 장기 원본을 보존합니다. 회사가 정한 주기(예: 주간)에 승인된 암호화 오프라인 매체로 DB 논리 백업, Storage 파일 전체, 객체 경로·크기·해시 목록을 함께 내보냅니다. 이것은 별도 실시간 DB/파일 서비스 도입이 아닌 복구용 오프라인 사본입니다. 운영 장치 접근자와 암호키 보관자를 제한하세요.
- Supabase Storage API를 이용해 파일을 페이지 단위로 내려받아 SHA-256을 계산하고 DB `attachments`와 대조합니다. 분기마다 별도의 테스트 Supabase 프로젝트에서 DB + 파일 복구를 훈련하고 실제 서명 다운로드까지 검사합니다. 복구 목표 시간과 허용 데이터 손실 시간을 회사가 결정해야 합니다. 자동 백업/export 스크립트와 운영 스케줄러는 이 버전에 포함하지 않았습니다.
- `meeting_revisions`, `task_revisions`, `ai_usage`는 직원에게 삭제 권한이 없습니다. 삭제 요청, 퇴사자 처리, 녹음 보존 기간, 개인정보 보유 근거는 사내 정책으로 정하고 관리자 SQL 작업도 별도 승인·감사로 남깁니다. 퇴사자는 계정 삭제보다 `active=false`로 비활성화해 기록 작성자 연결을 보존하세요.
- Storage 업로드 후 DB 연결 저장이 실패하면 고아 객체가 남을 수 있습니다. 앱은 오류를 알리며 자동 삭제하지 않습니다. 주기적으로 Storage와 `attachments.path`를 비교하고 보존 정책에 따라 관리자 확인 후 정리합니다.

## AI 비용 및 기밀

- 사용자별 한국시간 하루 요약 20회, 전사 10회, 회사 전체 100회. 예약 시 DB 잠금으로 원자적으로 집계하고 실패 요청도 포함합니다. 이는 요청 수 제한이며 원화/달러 기준의 정확한 청구 상한이 아닙니다. OpenAI 프로젝트 예산 알림·요금표·계정 한도를 함께 설정하세요.
- 요약 입력 메모 30,000자 + 전사 60,000자, 출력 6,000토큰 한도. 녹음은 파일 크기 제한만 있으며 압축률에 따라 길이/비용이 달라질 수 있습니다. 전사 토큰/오디오 시간별 과금 내역은 OpenAI 콘솔에서 대조합니다. AI 결과는 별도 테이블에 자동 저장하지 않고 사용자가 회의록에 반영·저장한 부분만 보존합니다.
- OpenAI의 해당 조직 데이터 처리/보관 정책과 회사 외부 전송 허용 범위를 확인하세요. 동의 확인란만으로 회사의 법적/보안 승인이 대체되지 않습니다. 접근 금지 기밀은 AI에 보내지 않고 수기로 기록하세요.
- 원문 인용 존재 여부를 코드로 검증하고 근거에 없는 담당자·날짜는 미정으로 돌립니다. 인용이 존재하더라도 AI 요약 자체가 사실과 다를 수 있으므로 모든 제품명·수치·결정·담당자·기한은 사람이 검토해야 합니다.

## 규모 확장 시

현재 목록은 500행씩 모든 페이지를 읽고 브라우저에서 통합 검색합니다(첫 500건에서 잘리는 방식은 아님). 기록이 수천 건 이상 쌓이기 전에 서버 검색/페이지 이동, PostgreSQL 한국어 검색 인덱스와 제품 정규화 테이블을 도입하세요. 사진 원본은 직접 공개하지 않으며 목록 미리보기에는 만료되는 서명 URL을 사용합니다. SSO/MFA 강제·감사 대시보드·권한별 제품 접근 분리는 별도 요구로 관리합니다.
