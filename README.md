# AZLA 주간회의 워크스페이스 v0.6

각 분류의 회의자료를 한 화면에서 보고, 회의 시작부터 종료까지 녹음한 뒤 원본·전사·요약을 따로 보관합니다. 직원 로그인과 작성자 표시는 없습니다.

## 화면과 입력

탭은 **신제품개발 → 디자인 → 생산관련업데이트 → 보류 → 중단 → 회의 녹음 내용** 순서입니다. 전체 탭은 없습니다. 각 탭에는 해당 분류로 등록된 안건만 표시됩니다. 다른 분류에 첨부한 이미지가 디자인 탭으로 자동으로 섞이지 않습니다.

- 첫 ‘새 주간회의’에서 날짜와 제목을 설정합니다. 새 회의는 한국시간 오늘 날짜를 제안합니다. ‘다음 회의 만들기’에서 요일과 관계없이 날짜를 선택한 뒤 이전 자료를 이어받습니다. 상단 ‘날짜 변경’으로 기존 회의 일정도 수정합니다.
- 각 탭의 ‘안건 등록 / 디자인 등록’에서 제목·제품·진행 내용·회의 결정과 이미지/PDF를 입력합니다. 진행 내용이 넓은 두 칸 입력 창에서 편집하며, ‘넓게 쓰기’로 한 칸에 집중할 수 있습니다. 하단 저장 버튼은 고정되고 Ctrl/Cmd+S도 지원합니다. ‘저장’은 창을 유지하고 ‘저장 후 닫기’는 창을 닫습니다.
- 프로젝트별 카드에서 큰 제품명·진행 내용·강조된 회의 결정·참고 이미지를 함께 봅니다. 여러 프로젝트가 있을 때 상단 바로가기로 같은 보드 안에서 해당 위치로 이동합니다. 새 작성/취합 화면을 나누지 않습니다.
- 이전 회의에서 바뀐 문장이 있으면 원문 중 해당 문장을 먼저 보여줍니다. ‘내용 펼치기’로 전체 원문을 원래 순서대로 읽습니다. 요약을 AI로 새로 만들지 않으며 저장 내용도 자동으로 바꾸지 않습니다. 인쇄에서는 변경 발췌 대신 전체 원문을 출력합니다.
- 진행 내용 본문은 PC에서 18px, 검정에 가까운 색으로 표시합니다. 예전 ‘다음 계획’ 필드는 새 입력과 취합표에서 제거했습니다. 기존 기록은 ‘이전 버전의 계획 기록’을 펼쳐 읽을 수 있으며 저장·복사·백업에도 보존됩니다.
- 작성/취합 전환 없이 한 프로젝트 보드를 사용합니다. 새 내용은 ‘안건 등록’, 기존 내용은 각 안건의 연필 모양 수정 버튼에서 편집합니다. 입력 창의 저장 또는 Ctrl/Cmd+S로 보관하고 같은 보드에서 확인합니다.
- 디자인 분류에서는 시안 확대·두 장 비교·승인/수정 요청·검토 이력을 사용합니다. 검토 결과는 자동 저장됩니다. 검토자 이름은 작성자 표시와 별개인 자유 입력 기록이며 본인 인증/전자서명이 아닙니다.
- 기존 버전의 ‘기타/협력업체’ 안건은 새 분류 확인 안내에서 옮깁니다. 데이터는 자동 삭제하지 않습니다.

## 이전 회의에서 이어 쓰기 · 안건 삭제

- **다음 회의 만들기**: 날짜를 정하고 진행 내용·결정·분류·이미지/PDF를 그대로 이어받아 변경된 부분만 수정합니다. 지난 회의는 독립적으로 보존됩니다. 파일 원본을 다시 업로드하지 않습니다.
- 선택한 날짜에 이미 준비한 회의는 다시 열며 작성한 내용을 덮어쓰거나 중복 생성하지 않습니다. ‘날짜 변경’에서 회의 날짜를 바꿀 수 있고, 별도 빈 회의가 필요하면 회의 도구의 ‘빈 회의 만들기’를 사용합니다.
- 이전 회의와 비교에서 두 회의를 나란히 보고 수정할 수 있습니다. 취합표는 변경 문장을 연한 초록색으로 표시하며, ‘신규·변경 안건만’으로 좁힐 수 있습니다. 비교 기준은 연결된 이전 회의의 현재 저장 내용입니다.
- 지난 시안의 검토 결과/이력은 ‘이전’ 표시로 보존합니다. 새 검토를 반영하면 이번 회의 기록으로 저장됩니다. 지난 녹음·전사·AI 요약과 회의 확정 상태는 이어받지 않습니다. 미완료 업무는 기존 업무 ID를 연결합니다.
- **안건 삭제**: 휴지통 버튼으로 해당 주차의 안건을 삭제합니다. 회의표와 이후 이월에서 제외하며, ‘삭제한 안건’에서 내용과 첨부 연결을 복원할 수 있습니다. 이전 주 회의와 파일 원본은 지우지 않습니다. 이미 만들어진 다른 주차에는 소급 적용하지 않습니다.

## 회의 시작 → 녹음 유지 → 회의 종료

1. ‘회의 시작’에서 참석자 동의와 AI 외부 전송을 확인하고 마이크 접근을 허용합니다.
2. 상단에 녹음 표시와 시간이 나타납니다. **분류 탭을 이동해도 녹음은 유지됩니다.** 녹음 중에는 다른 날짜 회의로 바꾸거나 회의를 복원하지 못하게 합니다.
3. ‘회의 종료’를 누르면 원본 구간을 저장하고 ‘회의 녹음 내용’ 탭으로 이동합니다.
4. AI 연결이 되어 있으면 한국어 전사 → 요약·논의·결정·후속 업무 취합을 자동 실행하고 각 단계와 최종 결과를 자동 저장합니다. 작성해 둔 안건을 덮어쓰지 않습니다.
5. 재생·원본 ZIP 다운로드·전사 원문 확인·요약 수정과 검토 후 저장을 지원합니다. AI 초안 저장과 사람의 검토 확인은 구분됩니다.

긴 회의는 4분마다 독립적으로 재생 가능한 녹음 구간으로 보관합니다(64kbps 요청, 브라우저별 실제 비트레이트 상이). 구간 전환 때 MediaRecorder를 재시작하므로 미세한 경계 공백이 생길 수 있습니다. 마지막 구간까지 저장한 뒤 전사를 시작합니다. 실패하면 원본과 이미 완료한 전사는 유지하며 다시 정리할 수 있습니다. 업로드 전 완료 구간을 브라우저 복구 캐시에 보관하고 저장 완료 후 캐시를 정리합니다.

**실제 자동 요약에는 Supabase 팀 공유와 OpenAI 연결이 필요합니다.** 미설정 상태에서도 로컬 녹음·저장·재생이 가능하며 ‘원본 저장 완료 · AI 연결 필요’로 표시합니다. 요약이 생성된 것처럼 표시하지 않습니다.

## 실행·공유 설정

```bash
npm ci
npm run dev
```

Node.js 22 이상(검증은 24). 환경변수가 없으면 브라우저 IndexedDB에 저장하며 기기 간 공유되지 않습니다. 공동 사용은 [설정 안내](docs/SETUP.md)에 따라 Supabase와 공유 링크를 연결합니다. DB와 비공개 파일은 Supabase 하나를 사용하고, 서버 키는 브라우저에 노출하지 않습니다.

v0.2의 `conference-v2.sql`을 이미 적용했다면 새 테이블 생성이나 초기화는 필요 없습니다. 기존 워크스페이스 JSON의 선택 필드로 녹음·이월 연결·삭제 상태를 보관하며 예전 자료도 읽을 수 있습니다. v0.1 데이터는 원본 테이블에 유지되며 별도 이관이 필요합니다.

## 백업과 부가 기능

회의 도구 메뉴에서 전체 ZIP 백업·복원, 저장 이력, PPTX 가져오기, 인쇄/PDF, 이전 내용으로 회의 만들기를 사용할 수 있습니다. 백업에는 회의자료·이미지·PDF·원본 녹음과 저장된 요약이 포함됩니다. 실제 회의자료나 원본 이미지는 공개 저장소에 포함하지 않습니다.

## 검증

```bash
npm run typecheck
npm test
npm run build
npm start -- --port 3100
# 다른 터미널. Chromium 필요
TEST_BASE_URL=http://localhost:3100 npm run test:browser
TEST_BASE_URL=http://localhost:3100 npm run test:readability
npm run test:access
```

브라우저 검증은 실제 Chromium MediaRecorder와 가상 마이크, 제어된 AI 응답을 사용합니다. 실제 OpenAI 호출/사내 회의실 마이크 품질/호스팅 Supabase 연결은 별도 인수 테스트 대상입니다.
